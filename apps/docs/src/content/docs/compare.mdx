**penciled.org** is an open-source JavaScript library and browser extension for persistent text highlights and notes. The library, published on npm as `penciled` and also called penciled.js, is 15 kB with its UI. It's a CSS Custom Highlight API library: it paints highlights without wrapping text in elements, and it comes with a toolbar, a note editor and saving to `localStorage` or your own backend. This page compares it with [Hypothesis](https://web.hypothes.is/) and five JavaScript libraries that highlight or annotate text: [mark.js](https://markjs.io/), [rangy](https://github.com/timdown/rangy), [web-highlighter](https://github.com/alienzhou/web-highlighter), [@recogito/text-annotator](https://github.com/recogito/text-annotator-js) and [Annotator.js](https://github.com/openannotation/annotator). They solve different problems, and for some jobs one of them is the better choice.

## What is the best open source text highlighting JavaScript library?

It depends on the job. For readers who highlight and take notes on your pages, penciled.org is the only one here that ships the toolbar, the note editor and persistence together and never modifies your DOM, in 15 kB. For highlighting search terms, mark.js. For a highlighter that must run in old browsers, web-highlighter. For collaborative annotation on the W3C model, @recogito/text-annotator. [Which one should I use?](#which-one-should-i-use) has the full list.

## Is penciled.org an alternative to Hypothesis?

Partly. Both let you highlight and annotate web pages, from a browser extension or from a script on your own site, but Hypothesis is a social annotation service and penciled.org is a local, private one. Hypothesis needs an account, stores annotations on its servers (or a server you run), and is built for sharing: public annotations, groups, replies and PDFs. penciled.org needs no account and no server. The [browser extension](/extension/) keeps highlights in your browser, and the penciled.org JavaScript highlight library saves to `localStorage` unless you plug in your own backend.

| | penciled.org | Hypothesis |
|---|---|---|
| What it is | JavaScript library and browser extension | Annotation service, with a browser extension and an embeddable client |
| Account | None | Required to annotate |
| Where annotations live | The reader's browser, or your backend through a [storage adapter](/recipes/rest-storage/) | Hypothesis's servers, or a self-hosted server |
| Sharing and discussion | No: highlights and notes are private | Public annotations, groups and threaded replies |
| PDFs | No | Yes |
| Changes to the page | None: painted with the CSS Custom Highlight API | Wraps highlighted text in elements |
| Customizing on your site | Full: options, CSS custom properties, custom actions or [headless](/reference/headless/) | Limited: it brings its own sidebar |

Choose Hypothesis when readers need to discuss a text with each other, or when you annotate PDFs. Choose penciled.org when readers keep their own highlights and notes, when you want the UI to match your site, or when nothing may leave the browser. Hypothesis isn't in the table below because it's a hosted service, not a library you bundle.

## Is there a CSS Custom Highlight API library for highlights and notes?

Yes: penciled.org. The [CSS Custom Highlight API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Custom_Highlight_API) lets the browser paint a range of text without adding elements, and penciled uses it for every highlight, with [no fallback](/guides/browser-support/#unsupported-browsers) that wraps text. Of the other libraries here, only @recogito/text-annotator has an optional renderer that uses it; by default it draws boxes in an overlay layer. mark.js, rangy, web-highlighter and Annotator.js wrap text in `<mark>` or `<span>` elements.

## Why does it matter whether a library mutates the DOM?

Wrapping highlighted text in `<mark>` or `<span>` elements works everywhere, but it changes the page underneath your code. Frameworks like React and Vue expect to own their markup, so a re-render can drop the highlights or fight with them, and highlights added before hydration can cause mismatches. Wrapping also splits text nodes and adds elements, which can break CSS selectors like `p > a` and scripts that walk the content.

The CSS Custom Highlight API lets the browser paint a range of text without any new elements, which is why penciled.org relies on it entirely. Recogito takes a middle path: its default renderer leaves your text alone but draws highlight boxes in a layer it adds to the container.

## Where does each alternative win?

- **mark.js** is the right tool for highlighting search terms. It handles keywords, regular expressions, diacritics and synonyms, it's smaller than penciled, it works in old browsers, and it has millions of weekly downloads behind it. penciled doesn't do search highlighting at all. mark.js hasn't had a release since 2018, but it's stable for what it does.
- **rangy** is a general Range and Selection toolkit: saving and restoring selections, text ranges, serialization and class application. If you need those primitives, or old browsers, it's broader than penciled, which only exposes what annotation needs.
- **web-highlighter** works back to IE 11 and is smaller than penciled. It's a headless engine with hooks to customize how highlights are serialized and restored, so you control everything, including the UI and storage you'll have to build.
- **@recogito/text-annotator** is the most capable annotation framework here. It's built on the W3C Web Annotation model, supports multiple users, has React bindings and a sibling PDF annotator, and is used in research and digital humanities projects. If you need collaborative annotation or W3C data end to end, start there.
- **Annotator.js** has a plugin system and a defined storage API, and Hypothesis was originally built on it. It hasn't had a release since 2015 and depends on jQuery 1.11, so it mostly matters if you already run it.

penciled is also new: it's below 1.0, so its API may still change between minor versions, and it has far fewer users than mark.js or rangy.

## Where does penciled.org win?

- **It never touches your DOM.** Highlights are painted by the browser, so React, Vue, Svelte and server-rendered pages re-render without losing them, and your markup, selectors and event listeners keep working. [Try it on the home page](/#b-dom).
- **It's a complete feature, not a toolkit.** `annotate('#article')` gives readers a floating toolbar, colors, a note editor, a hover preview, light and dark themes, keyboard shortcuts and screen-reader announcements. If you want your own UI, [`penciled/headless`](/reference/headless/) is the engine alone, at 6.4 kB.
- **Saving is built in.** Annotations persist to `localStorage` with no setup, or to your API through a [storage adapter](/recipes/rest-storage/). They're plain JSON, and [`toW3C()`](/recipes/export-import/#w3c-web-annotations) exports W3C Web Annotations.
- **It doesn't guess.** Each annotation stores its quote, the text around it and its position. When content changes, penciled finds it again, and when it can't be sure, it [sets the annotation aside](/guides/anchoring/) instead of highlighting the wrong words.
- **It's small for what it includes.** 15.3 kB with the full UI and one dependency, `@floating-ui/dom`. Importing it is safe during server-side rendering, and it ships TypeScript types.

## Which one should I use?

- To highlight **search terms** on a page: mark.js.
- To let **readers highlight and take notes** in modern browsers, without building the UI or storage yourself: penciled.
- To build **your own highlighter** that must work in **old browsers**: web-highlighter, or rangy for lower-level control.
- For **collaborative or research annotation** on the W3C model: @recogito/text-annotator.
- For **public or group annotation** of web pages and PDFs, as a service: Hypothesis.
- For **private highlights on any website**, as a reader: the [penciled.org browser extension](/extension/).
- For an **existing Annotator.js** deployment: keep it, or plan a migration; it isn't maintained.

## How were these numbers measured?

All figures were collected on 22 October 2026.

- **Size** is the package's full entry point bundled with all its dependencies, minified and gzipped by [size-limit](https://github.com/ai/size-limit) 14 with `@size-limit/preset-small-lib`, the same setup penciled's own size check uses. For rangy it's the four modules a highlighter needs. Annotator.js can't be bundled by size-limit, because it imports CSS and images, so it was bundled with esbuild, minified and gzipped at level 9, with its CSS and sprite inlined. Bundlephobia was rate-limiting requests at the time, so its numbers weren't used.
- **Last release** is the publish date of the `latest` dist-tag in the npm registry. For Annotator.js that's a 2.0 alpha; the last stable version, 1.2.2, is from 2012.
- **Weekly downloads** are from the npm downloads API for 12–18 October 2026.
- **License** is from each package's `package.json` or license file.
- **Old-browser support** is from each project's documentation and source.
