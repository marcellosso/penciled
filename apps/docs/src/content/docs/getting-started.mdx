**penciled** (penciled.org) is a 15 kB open-source JavaScript library for persistent text highlights and notes. Call `annotate()` on an element and readers can highlight text, write notes and find them again after a reload. Highlights are painted with the CSS Custom Highlight API, so your DOM is never modified.

:::caution[Pre-1.0]
penciled is below `1.0.0`, so the API may still change between minor versions. Breaking changes are listed in the changelog.
:::

**Browser support:** Chrome/Edge 105+, Safari 17.2+, Firefox 140+; no fallback on older browsers, `annotate()` only warns. See [Browser support](/guides/browser-support/).

<Steps>

1. Install the package.

   <Tabs syncKey="pkg">
     <TabItem label="npm">
     ```sh
     npm install penciled
     ```
     </TabItem>
     <TabItem label="pnpm">
     ```sh
     pnpm add penciled
     ```
     </TabItem>
     <TabItem label="yarn">
     ```sh
     yarn add penciled
     ```
     </TabItem>
     <TabItem label="bun">
     ```sh
     bun add penciled
     ```
     </TabItem>
   </Tabs>

2. Call `annotate()` on the element that holds your content, and import the default styles.

   ```ts
   import { annotate } from 'penciled';
   import 'penciled/styles.css';

   annotate('#article');
   ```

   `annotate()` accepts a CSS selector or an element. Readers can now select text inside it to highlight it in one of five colors, add a note, or click a highlight to change it.

3. Reload the page. Annotations are saved to `localStorage` as they change and restored when the page loads. No backend is needed.

</Steps>

## The styles

`penciled/styles.css` holds the toolbar, the note editor and the highlight colors. Import it once, from JavaScript as above or from CSS:

```css
@import 'penciled/styles.css';
```

Its selectors have zero specificity, so your own CSS wins. Only penciled's buttons and note field carry one attribute, so element resets like Tailwind's preflight can't strip them. See [Theming and customization](/guides/theming/).

## Name the document

Annotations are stored under a **document id**. By default it is the page's pathname, plus the container's `id` when it has one. In development penciled warns about this default, because in single-page apps the URL doesn't always identify the content. Pass your own id when the same page can show different content:

```ts
annotate('#article', { documentId: `post-${post.slug}` });
```

## Keep the instance

`annotate()` returns an instance for reading and changing annotations, listening to events and cleaning up:

```ts
const penciled = annotate('#article', {
  onCreate: (annotation) => console.log('Highlighted', annotation.quote),
});

penciled.getAll(); // every annotation, in document order
penciled.export(); // { version, documentId, annotations }
penciled.destroy(); // removes highlights, UI and listeners
```

See [Instance](/reference/instance/) for every method.

## Server-side rendering

Importing `penciled` is safe on the server: nothing touches `window` or `document` until `annotate()` runs. Call `annotate()` in the browser only, for example in an effect or a client-side script. In React, use the [React adapter](/recipes/react/).
